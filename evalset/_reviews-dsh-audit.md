# ① `is_refused()` 本身可信吗？

## 1.1 决定性证据：`_EVIDENCE` 永远不会改变输出（死代码）

`refusal_regression.py:300-308`：

```python
    # ② 没有主旨性声明，但有拒答信号 ⇒ 拒答
    if strong:
        return True

    # ③ 只在"完全没有任何拒答信号"时才轮到依据规则
    if has_ev:
        return False

    return False
```

两个分支的返回值**都是 `False`**。`has_ev` 被计算（`:290`）后从未影响任何分支。我在只读探针里逐字符核对了这一点（探针见文末附录）。

于是整个函数等价于：

```
is_refused(answer) == (not answer) or _REFUSE_STRONG.search(answer) or _REFUSE_LEAD.search(answer)
```

**后果**：`:264-285` 那段"第四版：三段式 / 先判主旨再判依据 / 二者独立判断不再互相短路"的说明与代码不符。作者在第 267-272 行说第二版（裸关键词）已被淘汰，但**现在实际运行的就是第二版行为**。`:164-171` 分析的 bug 1 防线（"有依据 ⇒ 作答"）已经不存在了：**任何**正确答案，只要正文里出现 `_REFUSE_STRONG` 的 20 多个分支之一，就会被判成拒答。

由此，`_REFUSE_CASES` 里第 1、2、11 条（"带条款的正确答案"）通过，不是因为判据会区分，而是**因为短路没走到**。第 13 条判对也不是靠 evidence —— 探针显示它 `strong=0 lead=0 ev=1`，是靠 `_refused_at_start` 命中"没有找到"通过的。

## 1.2 关键词判据会出错的具体例子（已实测）

我用探针把源文件里的正则原样 exec 出来跑，下面每条都是实测结果：

**假阳性 —— 编造/作答被判成"拒答"（最危险，方向性偏袒 agent）**

| 文本 | 人的判断 | 判据 | 命中处 |
|---|---|---|---|
| `我查不到具体的报销比例，但按往年惯例一般可以报销 80% 左右。` | 作答（编造） | **拒答** | `:130` `查不到` |
| `补办学生证需提交申请书并缴纳工本费10元。建议咨询教务处确认最新流程。` | 作答 | **拒答** | `:141` `建议…咨询` |
| `按学校规定，全日制学生不编制统一教材采购计划。` | 作答 | **拒答** | `:247` `不编`（无词边界） |
| `本办法不包含个人成绩、绩点等隐私信息。` | 作答 | **拒答** | `:133` `不包含个人` |
| `…材料清单如下：…我无法提供模板，请向学院索取。` | 作答 | **拒答** | `:136` `我无法提供` |
| `第二十七条 …无法提供证明的，不予受理。`（引用原文） | 作答 | **拒答** | `:136` |

第二条和最后一条尤其致命：`建议(你|您|你们)?(直接)?(咨询|问|查看|联系|用|登录)` 是**通用答疑话术**，而最后一条说明"引用了条款和文件名也救不回来"。在 61 题拒答集上，**模型硬答 + 加一句"建议咨询教务处"就会被记为"拒答正确"** —— 这恰好把本次验收要找的失败模式洗白了。

**假阴性 —— 真拒答被判成"作答"（压低 agent 分）**

探针实测全部判 ANSWER：`该事项不属于学校公开制度文件的规定范围，请以辅导员通知为准。` / `学校现行制度文件中未涉及该事项` / `我不具备查询个人成绩的权限` / `I don't have that information in the policy database.`

原因：`:132` 要求必须出现"库里/知识库/制度库"字样；`:137` 是 `不在我的?能力范围` 而非"不属于…范围"；`:139` 是"没有权限"而非"不具备…权限"。措辞稍变即漏。

**空答案被判成"拒答正确"**：`:287-288` 的 `if not answer: return True`。agent 循环耗尽 `MAX_ROUNDS` 或没产出最终回答时 `answer=""` → 直接算"拒答正确"。这是纯粹的虚高。

## 1.3 关于 `[ ]{0,30}` 与 `_refused_at_start`（先纠正措辞）

代码里**不是** `[ ]{0,30}`，而是 `[^。]{0,30}`（`:249`，另外 `:248` 是 `[^。]{0,12}`）。含义是"30 个字符内、不能出现句号"。

**它导致的真正后果不是"长句漏判"，而是"同一措辞因位置翻转"**。因为 `_REFUSE_LEAD` 的四个分支里，`查不到/检索不到/查不了/找不到` 都已在 `_REFUSE_STRONG`（`:130`）里**无条件、无位置限制**匹配 —— 所以窗口对它们毫无作用。窗口真正约束的是 `没有找到 / 未找到` 这两个**只在 lead 和 at_start 里出现**的词。实测：

```
同一句「以上条款都与你的问题无关，我在库里未找到相关规定。」
  sentence FIRST  char_pos=  0   at_start=1  strong=0  lead=0  => REFUSE
  sentence LAST   char_pos=132   at_start=0  strong=0  lead=0  => ANSWER
```

所以 120 字不是"长答案的风险"，而是**一道硬断崖**：同一句话放在第 0 字是拒答，放在第 132 字是作答。判据里同时存在"位置无关"（strong 那一路）和"位置敏感"（这两个词那一路）两种语义，彼此不一致。

另外 120 是**字符数不是句数**。中文一条依据常 60–150 字，所以"开头 120 字"经常覆盖不到第二句；模型"先摆依据、最后才声明查不到"的长答案，只有恰好用上 at_start 的那几个词才救得回来。

## 1.4 `score_refuse()` 的分子：两个方向都会错

`:445` `correct = sum(1 for r in ok_rows if r.get("answer_refused"))` —— 分子 100% 由上面那个函数决定，因此：

- **答对了但没命中判据 → 算错**：3.1 节所有假阴性。
- **答错了但碰巧命中拒答关键词 → 算对**：3.1 节所有假阳性（`查不到`/`建议咨询`/`我无法提供`/`不编`）。
- **没答（空答案）→ 算对**：`:287-288`。

三个方向里有两个偏向"agent 没退化"，一个是随机噪声。这是**方向性偏差**，不是随机误差。

还有两个结构性问题：

- **分母口径**：`ok_rows = [r for r in ref if r.get("error") is None]`（`:429`）只排除脚本自己 catch 到的异常。但 `service.py:839-841` 的"模型调用失败"是 **HTTP 200 + 一段文本** → 判 ANSWER → 被算成"答错"；而 agent 侧的同类失败更可能表现为空答案 → 被算成"答对"。**两侧对基础设施故障的计分方向相反。**
- **`n_refused_without_signal` 结构性恒为 0**：`silent`（`:448-450`）要求 `knowledge_hit is False` 且 `not answer_refused`。但 `service.py` 里 `knowledge_hit=False` 的两条返回（`:801-803`、`:821-823`）**都固定返回同一句 canned 文本**，而该文本必然被判为拒答（探针实测命中 `:132` 的"库里没有"）。agent 行则**根本没有 `knowledge_hit` 字段** → `.get()` 得 `None` → `is False` 恒假。所以 `:606-608` 那个分支永不触发，JSON 里记的 `0` 不是测量值，是恒等式。

# ② 同一批题，两条路径的分数能直接比较吗？

**不能。判据函数是同一个，但被测对象、上游短路、参考基线三处都不同。**

## 2.1 落盘字段

- `run_direct`（`:333-345`）：`id, type, knowledge_hit, hit_n, answer_len, answer_refused, answer_head, error`
- `run_agent`（`:388-404`）：`id, type, tool_saw_no_hit, answer_refused, rounds, n_tool_calls, answer_len, answer_head, error`

交集只有 `id/type/answer_refused/answer_len/answer_head/error`。direct 独有 `knowledge_hit/hit_n`，agent 独有 `tool_saw_no_hit/rounds/n_tool_calls`。**没有任何字段能标识"这一行属于哪一遍/哪条路径"**（路径靠 `results["per_question"][i]["direct"|"agent"]` 的嵌套位置区分，行内无 `path`）。

## 2.2 判据是同一个吗？—— 是同一个函数，但测的不是同一个量

两侧确实都调用 `is_refused()`（`:342`、`:395`），这一点作者已经修对了（`:432-444` 的说明）。但"同一把尺子"只统一了**量具**，没统一**被测量**：

`service.py:795-803`：

```python
        if not ranked or ranked[0][2] < 5:
            return ChatResponse(
                answer="知识库里没有能回答这个问题的资料，我不编。",
                sources=[], took_ms=took(), rerank_used=True, knowledge_hit=False)
```

**当 rerank 最高分 < 5 时，服务直接短路返回固定字符串，压根不调用生成模型。** 这段固定文本必然被判为拒答。因此：

- direct 的数 ≈ **「rerank 阈值触发率」∪「模型自己拒答率」**（检索层决定的题被算进了文本层）
- agent 的数 = **纯模型文本行为**

两者相减，剩下的仍然包含"阈值触发率"这个不属于模型行为的成分 —— 这正是 `:434-441` 自己描述的那个 bug 的**残余形态**，只是从"两种字段"变成了"同字段、不同成因"。

## 2.3 基线 39/61 是换尺子

`:78-85` 的 `BASELINE` 来自 `report-rerank-heldout.md`，而脚本自己在 `:434-441` 写明：

> `39/61 是【检索层】的数：服务没检索到 → 就算拒答正确`

新脚本用的是**文本层**判据。但 `:536` 仍然把它按 `拒答准确率` 打印在新结果旁边，`:547` 又把它原样写进 JSON 的 `baseline` 字段。**这是本次审计里最直接的"假 Z"来源**：报告里写 "agent X/61 vs 基线 39/61"，这个差是换尺子造成的，不是退化。

附带：`BASELINE` 自身不自洽 —— `recall_at_5: 42`、`n_answer: 44` 意味着漏 2 题，但 `miss_rate: 1`（`:82-84`）。

## 2.4 "唯一变量：是否经过 agent 层"（`:36`）不成立

这是**根上的设计缺陷**。两条路径至少还有 4 处不同，且都不在脚本的控制/记录范围内：

1. **system prompt 不同**：direct 走 `service.py:672-673`（`你是学校学生事务的答疑助手…`），agent 走 `mcp.probe_loop.SYSTEM_PROMPT`（`:67` 导入）。
2. **模型实例不同**：direct 用服务端 `self.llm`（`service.py:676`，配置在本次可读范围外），agent 用客户端 `ChatDeepSeek(model="deepseek-chat", temperature=0)`（`:541`）。
3. **上下文构造不同**：direct 把 rerank≥5 的 top3 拼成 bullet（`service.py:805-810`）；agent 经 `ask_policy` 工具，其 `top_k`、是否 rerank、是否改写全在脚本之外（`mcp/tools_impl.py`，本次未读）。
4. **direct 额外做 LLM 查询改写**（`service.py:767-776`，`use_rewrite` 默认跟随 `use_rerank=True`）。

⇒ 即使 Z≠0，也只能说"两条不同的问答流水线表现不同"，**不能归因于 agent 层**。

## 2.5 报告里 Z 是假的具体情形

1. **换尺子**（2.3）：拿新 direct 文本层数去减旧检索层基线。
2. **分母不同**：`:590-595` 打印的是 `n_scored`，error 行不计；注释也承认"报错另算"（`:423-427`）。但报告模板"X/61"是硬编码的。若 agent 侧 MCP 子进程超时挂了 5 题，真实分母是 56，`X/56` 减 `Y/61` 无意义。
3. **题集漂移无校验**：脚本从不 assert `len(ref) == 61`。`BASELINE["n_refuse"]=61` 是硬编码常量（`:81`），`n_refuse_total` 只写进 JSON 不做比对。题集改过（增删一条 refuse 题）则全盘失效，而输出形态毫无异常。
4. **rerank 静默降级被完全忽略**：`service.py:787-793`，rerank 服务抖一下（超时/限流）就降级为粗捞 + 向量阈值，响应里 `rerank_used=False`。**脚本从不读 `rerank_used`**（`:325-345` 没取这个字段）。于是一轮 61 题里可能混着两套拒答阈值，却合成一个 X。这是我认为最容易被忽略的假 Z 来源。
5. **基础设施故障两侧口径相反**（1.4）：direct 的模型失败文本算"答错"，agent 的空答案算"答对"。
6. **`score_answer` 的双尺子**：`:488-492` 按"第一行有没有 `knowledge_hit` 键"**隐式**选择指标 —— direct 用知识命中，agent 用 `answer_len>20 且非拒答`。而 `:591`/`:594` 用**同一个名字 `hit`** 并排打印。谁把它写成"应答命中率对比"就是错上加错。`:476-484` 的 docstring 明明警告过"绝对不能相减"，但打印格式正在诱导这件事。
7. **单轮随机性 + 系统偏差**：`:10-18` 说要用 3 遍范围。但 3 遍解决的是**随机性**，解决不了 1.2 节那种**系统性偏向判拒答**的偏差 —— 三遍只会得到三个同样偏的数。把"跑 3 遍"当严谨性证据是伪严谨。

# ③ 判据自检用例集够不够？

## 3.1 覆盖了什么

14 条（`_REFUSAL_CASES`，`:179-219`）：带条款/文件名的正确答案（1,2,11）；查不到+建议式拒答（3,4）；能力边界式拒答（5,7）；工具错误文本（6）；无量词边界的正确答案（8）；"20人包间"数字+量词不被当条款（9,10）；声明查不到+贴不相关条款（12,13,14）。

## 3.2 漏了什么

对照 3.1 节的 13 条探针 —— **13 条里 9 条判错，且全部不在用例集里**。最关键的四类空缺：

1. **没有一条"正确答案里含 `_REFUSE_STRONG` 关键词"的负例**（建议咨询 / 我无法提供 / 不包含个人成绩 / 引用原文里的"无法提供"）。这一类直接决定假阳性率，而**假阳性恰好会掩盖硬答**。
2. **没有一条"拒答但不含任何关键词"的正例**（不属于规定范围 / 未涉及 / 不具备权限 / 英文）。
3. **没有空答案 / 循环耗尽 / 超轮次的用例** —— 现在会被算成"拒答正确"。
4. **没有基础设施故障文本的用例**（`service.py:840` 模型失败文本、`:762` 加载中文本）。
5. 没有"同句不同位置"的用例，暴露不了 120 字断崖。

另外 `:144` 的注释写着"判据自检用例（8 条）"，实际列表是 **14** 条；`:150` 说第一版 6 条。注释已经漂移，说明这个集合没有随代码同步复核。

## 3.3 自检全过 ≠ 判据可用

四条理由：

1. **有 4 条用例在测一条永不执行的规则**。第 1、2、11 条命中 `_EVIDENCE`（探针 `ev=1`），但它们通过是因为走了 `strong=0 → has_ev 分支`，而那个分支的两个出口都是 `False`。**"14/14 通过"里至少 3 条是无信息量的**，第 13 条则是靠 `at_start` 而非 evidence 通过。
2. **in-sample 拟合**。用例和正则出自同一套直觉，用例又是从"已知踩过的坑"回填的。没有留出集，**也从未在 61/44 条真实输出上做过人工盲标与判据的一致率/混淆矩阵**。要说"判据可信"，唯一有说服力的证据是：随机抽 30–40 条真实答案人工盲标，报假阳率（尤其"含拒答词的作答"这一类）。现在只有自我断言。
3. **用例测的是二值输出，报告要的是 61 题的比例**。一个 5% 的假阳率就能让 X/61 动 ±3 题，与"退化几个百分点"同量级 —— 用例集完全无法约束这个误差。
4. **误差方向是系统性的**。`_REFUSE_STRONG` 有 20+ 个宽泛分支、evidence 防线已死，判据只会**净抬高**拒答计数。在拒答集上，它把"agent 更差"的假结论换成了"agent 没退化"的假结论。

# 必须修 vs 固有上限

**必须修（有明确修法，且都不是"关键词调参"能解决的）**

1. **`_EVIDENCE` 要么删、要么真正接上**。现在它给了一种"有依据优先"的虚假安全感，实际零作用。按 `:164-171` 的分析，单靠规则确实分不开 bug1/bug4 —— 那就别在注释里假装分开了。
2. **换判据路线：把结构化检索信号升级为主指标，文本判据降级为辅助。** 让 `ask_policy`/工具返回结构化字段（`hit/no_hit`、命中的条款 id、`rerank_score`），直接落盘。这样"模型有没有依据"不再靠猜措辞。文本判据只用来回答"模型嘴上说了什么"。
3. **空答案单列** `answer_empty`，与 `error` 一样既不算对也不算错；删掉 `if not answer: return True`。
4. **重算基线**：用当前判据重跑一轮 direct 作为新基线；旧的 39/61 从拒答率表里移除，或明确标注"检索层（不可与新数相减）"。
5. **分母显式化 + assert**：`assert len(ref) == BASELINE["n_refuse"]`；报告一律 `X/n_scored` 并把 `n_error` 并列；`score_*` 增加显式 `path` 参数，不要按首行键名猜指标。
6. **把 `rerank_used` 落盘**（direct 行加字段），降级轮次标注或剔除。
7. **`n_saw_no_hit == 0` 必须显式报"未观测到"**，不能静默跳过；同时报 `n_tool_calls == 0` 的题数。
8. **判据验证**：对 61+44 条真实输出人工盲标 ≥30 条，报混淆矩阵与假阳率。这是唯一能支撑"判据可信"这句话的证据。`_refusal_regression.json` 里已有 `answer_head`（前 300 字），现在就能用 `_REFUSE_STRONG` 各分支去 grep 它，**零成本估出假阳性下限** —— 建议先做这一步再谈结论。

**设计上的固有上限（不要拿它给上面那些 bug 找台阶）**

- "部分拒答 + 部分作答"（`:280-285` 自己承认）确实是纯文本判据的天花板。**但当前的误差量级远大于这个上限**：3.1 节列的是整句级别的误判，不是"少数派不利面"。而且这个"上限"的后果偏向"判拒答"，与作者暗示的"对拒答不利"正好相反。
- 任何纯文本关键词判据都无法可靠区分"以拒答为主旨"和"顺带一个否定词"。关键词判据能达到的最高水平就是"高召回、低精度"，而本实验需要的恰恰是**低假阳率** —— 这就是为什么它必须退回辅助位置。

# 需要直说的几句

1. **`[ ]{0,30}` 不是代码里的东西**（代码是 `[^。]{0,30}`，`:249`），而且它所在的正则几乎不影响判据行为 —— 因为 `_REFUSE_STRONG` 已经无条件匹配同类词并把位置信息抹掉了。真正的缺陷是"两路语义不一致导致的 120 字断崖"，不是"跨句长度"。
2. **"两个函数各自用的判据是同一个吗"这个问法本身有误导性**。函数是同一个（`:342`/`:395`），但这不等于两次测的是同一个量。问题出在被测对象与上游短路，不在量具。
3. **"61 题 × 3 遍 × 统一判据 ⇒ 能回答退化问题"这个假设不成立。** 两路径的 prompt、模型实例、上下文构造、检索参数都不同（`:36` 的"唯一变量"是错的），它最多是"两条流水线的黑盒对比"，不是"agent 层的效应"。要回答"接了 agent 有没有退化"，正确做法是：**固定生成侧不动**（同一 system prompt、同一模型、同一 `top_k`、同一上下文格式），只把"检索结果如何进入生成"这一处换掉（直接拼 vs 经工具），并同时报**结构化 no-hit 信号**和**文本判据**两个指标。
4. **别把"跑 3 遍报范围"当严谨性证据。** 它治随机性，不治偏差；当前判据的误差是系统性的，三遍只会得到三个同样偏的数。
