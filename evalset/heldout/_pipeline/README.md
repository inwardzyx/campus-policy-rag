# held-out 题集的构造流水线（三轮盲出题）

这一目录放的是**独立验证集（105 题）是怎么来的**——原来它们只活在作者本机的临时目录里，
于是 README/RESULTS.md 里那些数字（`39/61`、`Recall@5 42/44`…）的**来源说明没有落盘**。
现在补齐：脚本 + 盲出题的原始输出都在这里。

## 这条链怎么走的

| 文件 | 干什么 | 备注 |
|---|---|---|
| `../make_pack.py` | 生成**出题包**：`source_policy.md`（全库校规原文，**不含 chunk/向量/检索信息**）+ 模板 + 给出题人看的 `../README.md` | 已在仓库里；它保证"作者只看得到原文" |
| `build_heldout_prompt.py` | 拼**第一轮**的 prompt（说明书 + 校规原文，**没有**现有 20 题、没有任何工具） | 产出的包只投喂给出题人，不入库（可从本脚本 + `source_policy.md` 复现） |
| `build_heldout_r2.py` | 第二轮：**只给"已覆盖的条款名"**（不给题面）+ 拒答题按 6 类各 ≥5 道 | 同上 |
| `build_heldout_r3.py` | 第三轮：拒答题 25 道 + answer 5 道收尾 | 同上 |
| `extract_heldout.py` | 从**出题人的原始输出**里抽成 `questions.json`（只打印统计，不打印题面） | 第一轮 |
| `merge_heldout_r2.py` | 抽取 → 校验 → 与第一轮合并（**第一轮存档**，保证旧数字可复现） | 产出 `questions-r2.json` |
| `merge_heldout_r3.py` | 抽取 → **文本 + 语义双重查重**（新题与任一同型题余弦 > 0.93 就丢）→ 合并 | 产出 `questions-r3.json` |
| `patch_heldout.py` | 给出题包打补丁：`ALREADY_COVERED` 改成**从 `questions.json` 取 gold**（单一真源）、清掉 README 里 2 篇/68 条时代的过期文字、底本加时间戳与语料构成 | 记录"这份快照是哪一版" |
| `_blind_out/r1.md`、`r2.md`、`r3.md` | **出题人三轮的原始输出**（即"盲"的直接证据） | 抽取/合并的输入 |

## ★ "盲"是怎么保证的（这是 held-out 成立的前提）

1. 出题人拿到的是**全新会话**（不带任何历史），只看到 prompt 里的文字；
2. **不给它任何工具、不加 `--add-dir`、工作目录设成一个空目录** ——
   它没有任何通道去读仓库、评测集或 chunk；
3. prompt 里只有出题说明书 + 校规原文：**没有**现有 20 题、没有检索信息；
4. 第二、三轮额外只给"已覆盖的**条款名**"（不给题面），所以出题人对"别人问过什么"仍然是盲的。

## ⚠️ 复现这件事的边界（写清楚，免得以为一条命令能重来）

- 这几个脚本里带**本机绝对路径**（`D:\dsh-work\...`）：那是当时的**临时落点**（出题包与原始输出）。
  原始输出已经收进 `_blind_out/`；出题包本身**没入库**（它 100KB+，且可由脚本 + `source_policy.md` 重建）。
- "盲"依赖的是**流程约束**（上一条那四点），不是某段代码 —— 换机器重跑时，那四点是必须自己保证的。
- 三轮的题数与配比见 `RESULTS.md`；最终合并结果见 `questions.json`，分轮存档见 `questions-r1/r2/r3.json`。
