## Q1 两层划分成立吗

**[MAJOR] 两层图作为“讲解框架”成立，作为“建设项目”不成立——“数据层”在你的仓库里已经存在约九成，你真正缺的只有三小块。**

- **后果**：若照图建接口层，是给单人单仓加一层没有第二个消费者的间接层；面试官问“接口代码在哪、谁在调”时，答案只能是“没有”。

## Q2 三刀砍得对不对

**[MINOR] registry：砍对了，但“git 版本化就够”这个理由只对了一半。**
- **依据**：git 管不了两件事——kb_data 语料走 manifest 信任制（`runstate.py:320` 明写“取 manifest 的 content_hash，**不是文件字节**”，绕过 API 直接改文件指纹不动）；heldout 105 题无任何校验和/版本字段，只有自由文本 `_说明`（grep 无 sha/version）。而 registry 的职能其实已由 manifest.json + runstate 双件套承担，不是没人管。
- **后果**：DECISIONS.md 若写“git 就够”，被问“上传的语料和评测集呢”会卡壳；heldout 这块现在确实是裸的。
- **动作**：理由改写为“registry 模块砍掉，职能由 manifest+runstate 承担；补 heldout 校验和”。

**[MAJOR] replay：砍对了，但“promptfoo 的 caching 已覆盖”这个理由被你自己仓库直接反证。**
- **依据**：你的配置**强制 `--no-cache`**，坑 5 原文：“缓存键不包含‘被评测服务的内容’，服务改了也可能命中旧结果”（`eval/promptfooconfig.yaml:37-40`、`eval/README.md:146-148`）。replay 职能的真实替代品也不是缓存，而是 `RecordedTransport`（`kb/evalkit/transport.py:40-58`）+ runstate 的工作区 diff 快照。
- **后果**：这是全部记录里**唯一会被自己仓库反证的一句**。DECISIONS.md 本身是 4 项之一、是给面试官看判断力的文档——在里面写一句自己的 README 能当场戳穿的解释，伤害的恰是你的核心人设。
- **动作**：改写为“promptfoo 缓存在本仓必须关（实测坑 5）；复现靠 runstate 快照 + RecordedTransport，故不需要 replay”——这反而是更好讲的面试故事（见 Q3）。

**[MINOR] plan：砍对了。**
- **依据**：两仓库 grep 无任何变更分级痕迹；其唯一来源就是那两篇单公司帖；`scripts/rollback.py:33-42` 的三风险分类（代码 commit/工作区 diff/.env）已是这个规模下“分级”的真实形态。
- **后果**：无。
- **动作**：DECISIONS.md 用一句话保留纪律（“何时全量重跑 vs 抽样”），不建模块。

## Q3 与现成工具的边界

**[MINOR] 边界划对了：promptfoo 只当调度器，自研四样都有“它没有”的实据——这个面试论证站得住。**
- **依据**：promptfoo 官方断言三层=确定性/模型判/轨迹与 trace-span（已对官方文档核实，见文末来源），但**没有**配对显著性门禁、没有评分者 κ、没有“被测服务状态”的指纹（它的缓存键只含 provider+prompt+变量）。你的仓库恰好每样都有：`kb/loopgate.py:46-136`（McNemar+净增+无回退+拒答翻转+泄漏五重判）、`kb/attribution.py`（8 桶）、`kb/runstate.py`。且你的集成方式正确：判分复用 `run_eval.py` 不抄第二份公式，promptfoo 只管调度和退出码。
- **后果**：正面。“我评估过 promptfoo 并决定不用它做 X”站得住——条件是能先说出它有什么（三层断言、缓存、报告），再说你的 X 是它没有的。你还有比查文档更硬的牌：坑 5 是**实测出的缓存边界**，不是印象。
- **动作**：面试话术从“我决定不用”升级为“我用了它做调度，并实测出它缓存键不含被测服务内容，所以强制 --no-cache”。后者是“读过源码级”的信号。

## Q4 四条判据的“假绿”审计

- **后果**：写进 README 当能力，与你“不构成证据不下结论”的人设正面冲突。
- **动作**：降级为真话：“影响面靠 runstate 指纹 diff + 全量重跑发现”，并把这次过期报告事件作为该纪律的案例写进 DECISIONS.md。

**[MAJOR] ②（四级追溯链）在旧路径真绿，但你最新建的 promptfoo 路径疑似没接指纹——最严的门没装在最新的门上。**
- **依据**：run_eval/runstate 路径的链是闭合的：语料（manifest hash + docs 逐文件 sha256，`runstate.py:317-402`）、prompt/代码（内联常量由 git sha + worktree.diff 钉住，`runstate.py:23-27` 的设计理由原文即是此事）、环境（requirements 精确 pin）。切块/索引没有独立版本，但它们是（语料哈希×代码版本）的确定函数，“指纹即索引版本”这个语义站得住。但 `eval/reports/BASELINE-*.md` 落款只有日期，未见 runstate 指纹。
- **后果**：面试演示若从新路径讲，讲的机制却只在旧路径成立。
- **动作**：`case_server.py`/`summarize.py` 跑批接入 runstate.capture，把指纹写进 BASELINE 报告头；同时明说“切块/索引版本是派生量，不物化”（索引不落盘对 2104 块的 brute-force numpy 是合理设计，不是缺陷）。

**[MINOR] ③（命中定义改了→报告自动跟着变）半绿，且你自己已如实记录了反例。**
- **依据**：判分单源 + 报告全脚本生成（`run_eval.py:269`、`summarize.py`、`render_regression_report.py:29`）+ README 数字对账器，离线层零 API 成本、重算便宜；但“自动”不成立——每份报告手动重跑，且现存两份过期报告挂着（`eval/README.md:127-133`）。

- **动作**：先按你自己已写的建议把两份旧报告标为历史快照，再加一条“重生成全部报告”命令，之后才敢写③。

**[MINOR] ④（内容变了版本没变→报错）接近真绿，剩两个盲区，且缺“会红”的证明。**
- **依据**：run 级已真绿且语义优于“报错”——git sha、dirty 文件逐个 sha256、未跟踪文件聚合哈希全进指纹（`runstate.py:417-429`），改评测集必然换指纹，有测试（`tests/test_runstate.py:103`）。盲区一：kb_data 的 manifest 信任制（`runstate.py:320` 已知边界）；盲区二：heldout 无独立校验和文件。24 个变异脚本里没有一条覆盖④。

- **动作**：heldout 加 `questions.sha256` + checker + 一条 mutate；kb_data 补 file-vs-manifest 对账或在 runstate docstring 明说边界。
